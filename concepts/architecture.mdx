The SDK is three layers stacked on the Archer API. Each layer is optional. You can drop straight to the client if you want, or lean on the widget and never touch it.

## Layers

```text
              your app UI
                  │
                  ▼
   embed widget       React provider / view
         │                   │
         └─────┬──────────┘
               ▼
         ArcherWorkerClient
               │
     apiBaseUrl│(bearer token)
               ▼
           Archer API
         /              \
    Bridge (KYC,        Base RPC / bundler
    external accounts,  (USDC balance, user
    liquidation)        operations)
```

### `ArcherWorkerClient`

All network I/O lives here. It:

- Exchanges a **subject token** for an Archer **session token** and caches it in memory.
- Talks to the Archer REST API (`/account`, `/transaction_history`, `/offramp/*`, `/bridge/*`, `/wallet/intent/*`).
- Reads the end user's on-chain USDC balance via viem, given an RPC URL.

It has no UI, no framework dependency, and no persistent storage.

### `@archermoney/sdk/react`

`ArcherWorkerProvider` owns one `ArcherWorkerClient`, calls the common endpoints in parallel, and exposes a React context via `useArcherWorker()`. `ArcherWorkerView` renders the prebuilt balance, history, and cash-out UI on top of that context.

### `@archermoney/sdk/embed`

A thin wrapper that mounts `ArcherWorkerView` into any DOM node and exposes `window.ArcherWorkerWidget.mount` so plain HTML pages can consume it.

## Key primitives

- **Subject token.** A JWT your identity provider signs. Identifies the end user to Archer.
- **Session token.** Short-lived bearer token the SDK gets from `/auth/token_exchange`.
- **Smart wallet.** Each Archer end user has a smart contract wallet on Base, provisioned on first login.
- **Wallet intent.** A structured description of a wallet operation (currently `erc20_transfer`) that the Archer API can prepare into a user operation.
- **Signed payload.** The host-produced signature that authorizes a prepared intent. See [Wallet authorization](/concepts/wallet-authorization).

## What Archer runs vs. what your app runs

| Runs in Archer | Runs in your app |
| --- | --- |
| Identity federation and token exchange. | User authentication. |
| Smart wallet provisioning and orchestration. | Wallet-authorization surface (Privy or similar). |
| Bridge integration (KYC, external accounts, off-ramp settlement). | Presenting Bridge status and links to the end user. |
| Transaction indexing and history. | UI, routing, and any product-specific screens. |
| User operation bundling and relay to Base. | Signing the user operation authorization payload. |
