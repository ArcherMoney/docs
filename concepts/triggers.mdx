A **trigger** is the channel that delivers events to an agent. Every agent fires from a **webhook** — your system `POST`s a JSON event to the agent's URL and Archer runs the reward.

## Webhook trigger

Archer assigns each agent its own URL on the **Agent** detail page:

```
https://api.archermoney.com/events/{webhook_token}
```

Your system `POST`s a JSON event to the URL and Archer fires the agent. No bearer token, no signature — the URL itself is the secret, so keep it out of client-side code and source control.

**Best for**: anything programmatic. CRMs, product backends, CI pipelines, marketing automation, internal tools.

See [Sending events](/developers/sending-events) for the request shape, idempotency, and retry guidance.

## Pausing a trigger

Set an agent to **Paused** from its detail page (the "Agent is active" toggle) to stop processing without losing the webhook URL. Events received while paused are accepted and silently dropped — they will not be replayed when you reactivate the agent.

## Common signal sources

| Signal source | How to wire it |
|---|---|
| Your backend / product code | Webhook `POST` from your service |
| Your CRM or sales tool | Webhook `POST` from a workflow step |
| CI pipeline event | Webhook `POST` from a build step |
| A marketing automation step | Webhook `POST` from the automation tool |
| One-off internal request | Webhook `POST` from an internal tool or form |
