---
title: "Activity"
description: "Understand the Archer activity feed: how goods orders map to delivered and pending statuses, CSV exports, and the approval queue workflow."
---

The **Activity** view is the user-facing history of reward fulfillment. It is sourced from goods orders created by the agent runtime and surfaced through `/activity`.

## Activity rows

`GET /activity` returns rows projected from goods orders. Only two statuses are user-visible:

| Frontend status | Backing order status | Meaning |
|---|---|---|
| `delivered` | `fulfilled` | The reward shipped or settled. |
| `pending` | `pending_approval` | The reward is waiting on admin or approver sign-off. |

Declined orders are hidden from the activity feed; they are visible to admins through the approval queue.

## CSV export

`GET /activity/export` returns the same filtered rows as a CSV file. Use it for accounting, reconciliation, or compliance archives.

## Approval queue

`GET /goods_order/approvals` returns only `pending_approval` orders. Approvers can approve or decline:

```bash
curl -X PATCH "https://api.archermoney.com/goods_order/approvals" \
  -H "Authorization: Bearer $ARCHER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "order_id": "ord_...",
    "decision": "approve"
  }'
```

Decisions:

- **`approve`** — order moves toward fulfillment and eventually appears as `delivered`.
- **`decline`** — order leaves the approval queue and is hidden from `/activity`.

Owner, admin, and approver roles can act on the queue; other roles can read it.

## Webhooks vs. activity

The activity feed is **not** an event log. It only shows fulfillment outcomes. To inspect raw incoming events or replay them, use the agent runtime's `EventRun` records (logged via CloudWatch and queryable through internal tooling).
