Import from `@archermoney/sdk/backend`. Use this client from a trusted server environment to provision worker accounts on behalf of your users. Unlike `ArcherWorkerClient`, it authenticates requests with an **API signer** (an EOA that Archer has authorized on your account) rather than a subject-token exchange.

```ts
import {
  ArcherBackendClient,
  ArcherBackendApiError,
} from "@archermoney/sdk/backend";
```

<Warning>
  Never ship this client to the browser. The API signer's private key must stay on your server.
</Warning>

## When to use it

- Bootstrapping worker accounts from your backend before the end user ever opens your app.
- Bulk-importing existing users into Archer from a script or job.
- Any server-to-server call where you cannot present an end-user subject token.

For everything a signed-in end user does in the browser (balances, history, cash-out), keep using [`ArcherWorkerClient`](/reference/client) with token exchange.

## Constructor

```ts
new ArcherBackendClient(config: ArcherBackendSdkConfig)
```

### `ArcherBackendSdkConfig`

| Field | Type | Notes |
| --- | --- | --- |
| `apiBaseUrl` | `string` | Archer API URL. Trailing slashes are trimmed. |
| `signerAddress` | `string` | Checksummed address of the API signer authorized on your Archer account. |
| `signMessage` | `(message: string) => string \| Promise<string>` | Callback that returns an EIP-191 `personal_sign` signature over the canonical request message. |
| `fetch` | `typeof fetch` (optional) | Override the global `fetch` for tests or custom transports. |
| `nonce` | `() => string` (optional) | Override the per-request nonce. Defaults to `crypto.randomUUID()`. |
| `timestampSeconds` | `() => number` (optional) | Override the request timestamp. Defaults to `Math.floor(Date.now() / 1000)`. |

## Request signing

Every request the client makes is signed by your `signMessage` callback and sent with four headers:

| Header | Value |
| --- | --- |
| `X-Archer-Signer-Address` | The `signerAddress` from your config. |
| `X-Archer-Timestamp` | Unix seconds when the request was built. |
| `X-Archer-Nonce` | Unique nonce for this request. |
| `X-Archer-Signature` | EIP-191 signature over the canonical message. |

The client builds a canonical message with the following newline-joined fields and passes it to `signMessage`:

```text
archer-api-v1
<lowercased host>
<uppercased method>
<request path>
<canonical, sorted query string>
<sha256 hex of request body>
<timestamp>
<nonce>
```

You rarely need to build this yourself — `ArcherBackendClient` handles it — but the helper is exported for testing:

```ts
import { buildApiSignerMessage } from "@archermoney/sdk/backend";
```

### Signing with viem

```ts
import { createWalletClient, http } from "viem";
import { privateKeyToAccount } from "viem/accounts";
import { ArcherBackendClient } from "@archermoney/sdk/backend";

const account = privateKeyToAccount(process.env.ARCHER_SIGNER_PRIVATE_KEY as `0x${string}`);

const backend = new ArcherBackendClient({
  apiBaseUrl: "https://api.archermoney.com",
  signerAddress: account.address,
  signMessage: (message) => account.signMessage({ message }),
});
```

Any signer that produces an EIP-191 `personal_sign` signature works — ethers, a KMS-backed signer, or a hardware wallet — as long as the resulting `0x…` hex string is returned from the callback.

## Methods

### `createWorker(request)`

```ts
createWorker(request: CreateWorkerRequest): Promise<ArcherBackendWorker>
```

Creates (or upserts) a worker under your Archer account by calling `POST /person`. Provide at minimum the worker's `email`. `externalUserId` is the recommended way to link the Archer worker back to your own user id.

```ts CreateWorkerRequest
interface CreateWorkerRequest {
  email: string;
  name?: string | null;
  externalUserId?: string | null;
  isArchived?: boolean;
}
```

```ts ArcherBackendWorker
interface ArcherBackendWorker {
  id: string;
  email: string | null;
  name: string | null;
  external_user_id: string | null;
  wallet_id: string | null;
  wallet_address: string | null;
  status: string;
  is_archived: boolean;
  account_id: string;
  message?: string;
}
```

#### Example

```ts
const worker = await backend.createWorker({
  email: "worker@example.com",
  name: "Worker One",
  externalUserId: "user_42",
});

console.log(worker.id, worker.wallet_address);
```

Once the worker exists, mint subject tokens for that user from your identity provider and hand them to `ArcherWorkerClient` in the browser to render balances, history, and cash-out.

## Errors

Non-2xx responses throw `ArcherBackendApiError`:

```ts
class ArcherBackendApiError extends Error {
  readonly status: number;
  readonly body: unknown;
}
```

Common statuses:

| Status | Typical cause | Recovery |
| --- | --- | --- |
| `400` | Missing or malformed fields (for example, invalid email). | Fix the payload; do not retry unchanged. |
| `401` | Signature invalid, timestamp too skewed, or nonce reused. | Rebuild the request (the client already refreshes the nonce and timestamp on each call). |
| `403` | `signerAddress` is not authorized on the account, or lacks the required scope. | Contact Archer to authorize the signer. |
| `409` | A worker with the same `externalUserId` or `email` already exists in a conflicting state. | Read the existing worker and reconcile. |
| `5xx` | Archer had an error. | Retry with backoff. |

```ts
try {
  await backend.createWorker({ email: "worker@example.com" });
} catch (err) {
  if (err instanceof ArcherBackendApiError) {
    console.error(err.status, err.body);
    return;
  }
  throw err;
}
```
