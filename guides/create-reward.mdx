---
title: "Create a reward"
description: "Step-by-step guide to defining a reward rule, picking the right category and trigger, and capturing its webhook URL."
---

This guide walks through creating a reward end-to-end. By the end you'll have a live reward with a webhook URL ready to receive events.

## Prerequisites

- An active Archer account (Owner or Admin role).
- An Auth0 access token. See [Authentication](/api/authentication).

## 1. Decide on the trigger

Pick the channel that will deliver events:

- **Webhook** (default): any system that can `POST` JSON.
- **Slack**: a teammate runs a slash command. Only one per account, and Slack must be installed first via [Connect Slack](/guides/connect-slack).

## 2. Choose a category

The category determines fulfillment routing:

| Category | Use it for |
|---|---|
| `office` | Internal swag and supplies. May go through admin approval. |
| `customer` | Gifts and incentives sent to end users. |
| `partner` | Affiliate or partner payouts. |

## 3. Write the logic

`logic` is plain English. Archer uses it as the reward's instruction at execution time. Make it specific:

- ✅ "When a referred user completes onboarding, pay the referrer $25 via the partner's saved payout method."
- ❌ "Reward partners."

Include the trigger condition, the recipient, and the reward amount or item.

## 4. Create the reward

```bash
curl -X POST https://api.archermoney.com/agent \
  -H "Authorization: Bearer $ARCHER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Referral payout",
    "logic": "When a referred user completes onboarding, pay the referrer $25",
    "category": "partner",
    "trigger_kind": "webhook"
  }'
```

The response includes the reward's `id`, `webhook_token`, and `webhook_url`. Store the URL — your producer needs it to send events.

## 5. Wire up your producer

Have your application `POST` events to the `webhook_url`. Include an `event_id` for idempotency:

```bash
curl -X POST "$WEBHOOK_URL" \
  -H "Content-Type: application/json" \
  -d '{
    "event_id": "evt_$(date +%s)",
    "type": "onboarding.completed",
    "referrer_email": "alice@example.com"
  }'
```

See [Send events](/guides/send-events) for payload conventions and retry behavior.

## 6. Verify

After a moment the reward execution appears on the [Activity](/concepts/activity) page or via `GET /activity`. Office and customer rewards may show as `pending` until an approver acts.

## Updating a reward

Use `PATCH /agent?agent_id=<id>` with any subset of `name`, `logic`, `category`, or `status`:

```bash
curl -X PATCH "https://api.archermoney.com/agent?agent_id=$AGENT_ID" \
  -H "Authorization: Bearer $ARCHER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"status": "paused"}'
```

The `webhook_url` does not change.

## Deleting a reward

`DELETE /agent?agent_id=<id>` archives the reward. Its webhook URL stops accepting useful events — incoming messages will be acknowledged and dropped at the agent runtime.
