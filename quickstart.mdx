This guide walks you through end-to-end integration: create a reward rule, capture its webhook URL, and `POST` a test event that triggers it.

## Prerequisites

- An Archer account at [archermoney.com](https://archermoney.com). New accounts are provisioned as Business accounts on first sign-in.
- An Auth0 access token for the API. Sign in to the dashboard and copy it from your developer settings, or use the Auth0 client credentials flow.
- `curl` or any HTTP client.

<Note>
  All protected endpoints accept the access token as `Authorization: Bearer <token>`. The Archer API is served from `https://api.archermoney.com`.
</Note>

## 1. Create a reward

`POST /agent` creates a reward rule. `name` and `logic` are required, and `category` must be one of `office`, `customer`, or `partner`.

```bash
curl -X POST https://api.archermoney.com/agent \
  -H "Authorization: Bearer $ARCHER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Onboarding completed",
    "logic": "When a referred user completes onboarding, pay the referrer $25",
    "category": "partner",
    "trigger_kind": "webhook"
  }'
```

The response includes the reward's `id`, `webhook_token`, and `webhook_url`:

```json
{
  "id": "5b2a...",
  "name": "Onboarding completed",
  "logic": "When a referred user completes onboarding, pay the referrer $25",
  "category": "partner",
  "trigger_kind": "webhook",
  "status": "active",
  "webhook_token": "0xabc...",
  "webhook_url": "https://api.archermoney.com/events/0xabc..."
}
```

## 2. Send a test event

Post any JSON payload to the reward's `webhook_url`. Archer accepts the event and returns `202 Accepted`.

```bash
curl -X POST "$WEBHOOK_URL" \
  -H "Content-Type: application/json" \
  -d '{
    "event_id": "evt_test_001",
    "type": "onboarding.completed",
    "referrer_email": "alice@example.com",
    "user_email": "bob@example.com"
  }'
```

Archer enqueues the event and the agent runtime resolves the `discriminant` in the URL back to your reward rule. Processing is idempotent per `(event_id, agent_id)` — sending the same `event_id` twice will not double-execute the reward.

<Tip>
  Always include an `event_id` you control. Archer uses it for idempotency and surfaces it on the Activity page for debugging.
</Tip>

## 3. Verify the result

Open the dashboard and check the **Activity** page, or call the API:

```bash
curl "https://api.archermoney.com/activity" \
  -H "Authorization: Bearer $ARCHER_TOKEN"
```

Fulfilled rewards appear as `delivered`; rewards waiting on approval (for example, office orders that require an admin sign-off) appear as `pending`.
