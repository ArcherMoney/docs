This quickstart mounts the prebuilt worker view in a React app. You need an Archer tenant id, an API base URL, and a way to obtain a subject token for the current end user (typically a JWT minted by your identity provider or your own backend).

## 1. Install

```bash
npm install @archermoney/sdk react react-dom
```

## 2. Mount the worker view

```tsx App.tsx
import { ArcherWorkerView } from "@archermoney/sdk/react";

export function App() {
  return (
    <ArcherWorkerView
      config={{
        apiBaseUrl: "https://api.archermoney.com",
        tenantId: "your-tenant-id",
        getSubjectToken: async () => {
          const res = await fetch("/api/worker-token");
          const { token } = await res.json();
          return token;
        },
      }}
      balance={{
        rpcUrl: "https://mainnet.base.org",
        usdcAddress: "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
        chainId: 8453,
      }}
    />
  );
}
```

The view renders available balance, the wallet address, a balance graph, the latest transactions, and a cash-out panel.

## 3. Enable cash-out

Cash-out requires the host to authorize the wallet operation. Pass `usdcAddress` and a `signAuthorization` callback:

```tsx
<ArcherWorkerView
  config={config}
  balance={balanceConfig}
  usdcAddress="0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913"
  signAuthorization={async (requestPayload) => {
    // Present requestPayload to your wallet-authorization surface
    // (e.g. Privy) and return the resulting 0x… signature.
    return signWithHostWallet(requestPayload);
  }}
/>
```

`signAuthorization` is called once for the [EIP-7702 delegation](/concepts/wallet-authorization) on first cash-out, and once per user operation after that. The view runs `ensureDelegatedWallet` automatically before its first submit.

See [Wallet authorization](/concepts/wallet-authorization) for the security boundary and [Cash-out flow](/concepts/cash-out) for the full sequence.
